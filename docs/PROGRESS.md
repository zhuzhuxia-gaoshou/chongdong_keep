### 3.1 阶段 0：后端找回或重建（⏸️ 已暂停，启动时从 0.0 开始）

#### 0.0 服务器勘察指南（开工时照此执行，约 30 分钟）

**原理**：后端程序不在本机，而是当年由伙伴「部署」到服务器上运行的——即他把代码复制进了 47.104.129.148 并在上面跑起来。程序能一直运行，就说明**源码文件一直在这台机器的硬盘上**（就像厨师回家了，厨房和菜谱还在你手里）。

**步骤**：

1. 登录阿里云官网控制台（买服务器时用的账号）→ 云服务器 ECS → 实例列表 → 找到 47.104.129.148 这台实例
2. 点「远程连接」→ 选 **Workbench 远程连接**（浏览器里直接开终端，无需输 IP/密码）
3. 在终端里逐条执行以下**只读**命令，把输出截图/贴给 AI 助手判读：

```bash
ls /root          # 最常见的部署位置
ls /home          # 次常见位置
ls /www 2>/dev/null   # 宝塔面板用户的话在这里
ps -ef | grep node    # 确认 node 服务在跑（看它的启动路径就知道代码装在哪）
pm2 list 2>/dev/null  # 若用 pm2 守护，能直接看到程序目录
docker ps 2>/dev/null # 若用 docker 部署，能看到容器
```

4. AI 判读后定位三样东西：**源码目录**（有 package.json 的文件夹）、**.env 文件**（数据库/JWT 密码）、**部署方式**（pm2/docker/宝塔/systemd）
5. 结论二选一：代码完整 → **接管现有代码**（建 Git 仓库把服务器上的代码纳入版本管理，几天搞定）；代码残缺 → 按 SPEC §四契约**从零重建**（几周）

**原则**：勘察全程只读、不删不改；旧服务保持运行（前端 Live 模式还连着它）。
